# Credit Card Fraud Detection

End-to-end binary classification pipeline for detecting fraudulent card transactions under severe class imbalance.

The project focuses on the parts of fraud modelling that matter in practice: stratified train/test separation, train-only resampling, reproducible preprocessing, probability-based evaluation, and persistent model artifacts.

## What this project demonstrates

- Python-based ML pipeline using pandas, scikit-learn, imbalanced-learn and XGBoost
- Stratified hold-out evaluation
- StandardScaler fitted on training data only
- SMOTE applied only to the training partition
- XGBoost classification for imbalanced tabular data
- ROC-AUC and Average Precision alongside class-level precision/recall/F1
- Saved model and preprocessing artifacts with joblib
- Reproducible JSON evaluation output

## Dataset

The implementation is designed for the public **Credit Card Fraud Detection** dataset originally released through the ULB Machine Learning Group and commonly distributed through Kaggle.

The CSV is not stored in this repository. Place it at:

```text
data/raw/creditcard.csv
```

Expected target column:

```text
Class
```

where `1` represents fraud and `0` represents a legitimate transaction.

## Methodology

### 1. Train/test separation

The data is split using a stratified 80/20 hold-out with `random_state=42` so the rare fraud class is represented in both partitions.

### 2. Preprocessing

`StandardScaler` is fitted on the training partition and then applied to the test partition.

### 3. Imbalance handling

SMOTE is applied **after the split and only to the training data**. The original test distribution remains untouched.

### 4. Model

The current classifier is an `XGBClassifier` configured with class-imbalance weighting and a fixed random seed.

### 5. Evaluation

The held-out test set is evaluated using:

- Precision, recall and F1 by class
- ROC-AUC
- Average Precision / PR-oriented performance

The exact observed metrics are generated by the code and written to `results/test_metrics.json`. This README deliberately does not publish hypothetical performance values.

## Current scope

This repository is an ML experimentation pipeline rather than a production fraud platform. It does not currently include a live API, streaming feature pipeline, drift monitoring, model registry, or calibrated decision-cost layer.

Those are natural extensions, but they are intentionally not presented here as completed functionality.
